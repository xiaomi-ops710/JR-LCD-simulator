# UI刷新の計画（案B：実機寄せ）

目的：操作を分かりやすくし、LCDの見た目を実機写真に近づける。

## 方針
- 色・文字・間隔は `css/tokens.css` に集約する（部品の中に色を直書きしない）。
- 1段階ずつ進め、各段階で回帰テスト（`tests/snapshot.py`）と実機表示での確認を行う。
- 表示の内容（駅・時刻・案内文）は変えない。見た目と操作だけを変える。

## 段階

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0. 土台 | トークン作成、計画作成 | 回帰テストが変わらない（済） |
| 1. 上部の帯 | 路線記号・行先の枠・次は/まもなくのラベル | 写真1・2の配置に近い。行先が隠れない |
| 2. 中段の表示 | 駅一覧・路線図・のりかえ帯・運行情報帯 | 写真5・6・9・10と同じ要素が揃う |
| 3. 操作パネル | 「よく使う操作」を前面に、詳細設定は折りたたむ | 初回利用で迷わず路線と駅を切り替えられる |
| 4. M3の部品 | ボタン・入力欄・タブをトークンで統一 | 操作パネルの見た目が統一されている |
| 5. 再現度の仕上げ | 文字位置・色・影を実機写真と見比べて調整 | 写真との差を言語化して残件が少ない |

## 注意
- ひらがな・地名が隠れないことを、段階ごとに長い地名で確認する。
- 音や時間で変わる表示は、テストの対象外（`SKIP_CLICKS`）のままにする。
- 確認は GitHub Pages（Tailwind CDN 読み込み）で行う。この環境では見た目を正確に再現できないため。

## 決めていただきたいこと
1. 路線色の目安（`tokens.css`）を、実機写真に合わせて確定してよいか。
2. 段階1から進めてよいか。
